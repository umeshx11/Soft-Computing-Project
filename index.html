3.4 — 3.4.5
3.4 · CONTROLLER ARCHITECTURE

From a flat controller to a hierarchy

A flat design sends inputs to one rule base. A hierarchical design splits a larger decision into smaller functional or control modules, often passing an intermediate linguistic or numerical result between them.

3.4.2.1

Feedback & filter modules

A filter smooths a noisy measurement before fuzzification. Feedback compares the measured output with a target and uses the error to adjust the next control action.

PREVIOUS FILTERED24.0
NEW FILTERED26.1
yf[k] = αx[k] + (1 − α)yf[k−1]
3.4.2.2

Functional & control modules

A functional module estimates a useful condition (such as thermal comfort). A control module maps that condition to an action (such as fan or heater demand).

01Sensor / estimatetemperature, humidity
↓
02Functional modulecomfort / thermal load
↓
03Control modulefan / heater command
The split improves organization, but the intermediate variable and module interfaces must be defined carefully.
3.4.3

Effect of information processing

Averaging, quantization, filtering, or delay can change the signal presented to the fuzzy sets—and therefore change the membership pattern.

The normalized overlap-entropy indicator is descriptive: it summarizes how spread out the three membership degrees are after normalization.

3.4.4

Signal combination & fuzziness

Combining fuzzy signals with different operators changes the resulting membership grade and can increase or reduce overlap.

05 / QUALITY OF A FUZZY CONTROLLER

Properties & rule-base analysis

A controller should do more than produce a number. Good design requires input-space coverage, bounded and usable outputs, valid and consistent rules, acceptable continuity, and an understanding of rule interactions and possible decomposition.

3.5 — 3.5.7.3
01Completeness

Every relevant input combination should activate at least one rule and produce a valid output.

02Continuity

Small changes in input should not create unexplained abrupt changes in the crisp output.

03Consistency

The same antecedent condition should not lead to contradictory consequents.

04Rule validity

Rules should use defined linguistic terms and should be capable of firing in the input domain.

LIVE DIAGNOSTICS

Check this rule base

Completeness is sampled on a finite grid. Continuity is reported as the largest neighboring output change on that grid; it is a diagnostic, not a formal mathematical proof.

3.5.7 · RULE-BASE DECOUPLING

Coupled vs uncoupled reasoning

R
Coupled rule base

One rule can depend on a combination of multiple inputs.

Uncoupled rule base

Independent input contributions are separated into smaller sub-rules.

Equivalence test (illustrative): R(i,j) = row(i) + column(j) + constant

The additive factorization test is a teaching diagnostic for this 3 × 3 ordinal decision table. It is not a universal equivalence theorem for every fuzzy architecture.

3.5.5 — 3.5.6

Rule validity & interaction

Overlapping membership functions mean multiple rules can contribute at once. This is expected; the important question is whether their combined consequents produce a sensible decision.

07 / QUICK REFERENCE

Key terms & algorithm summary

A compact reference for the terminology used throughout the chapter.

Viva preparation
Fuzzy set

A set in which an element has a membership grade between 0 and 1.

Membership function

A mapping from a universe of discourse to a membership grade.

Fuzzification

Converts crisp measurements into degrees of membership in fuzzy sets.

Rule base

A collection of linguistic IF–THEN rules encoding the control knowledge.

Inference engine

Evaluates the rules and constructs fuzzy output contributions.

Aggregation

Combines the fuzzy outputs of the individual rules.

Defuzzification

Maps an aggregated fuzzy output to a crisp control value.

Exploration vs precision

Membership overlap and rule interaction allow gradual decisions rather than hard switching.

MAMDANI FUZZY CONTROL · PSEUDOCODE

The complete control cycle

  1. Read crisp sensor inputs.
  2. Fuzzify each input using its membership functions.
  3. Evaluate each IF–THEN rule with a fuzzy AND operator.
  4. Apply each firing strength to its consequent fuzzy set.
  5. Aggregate the individual rule outputs.
  6. Defuzzify the combined output to obtain a crisp action.
  7. Apply the action and repeat with the next measurements.
